# 音乐页 v1.4.7

音乐页采用白底布局：顶部是北京时间、日期、星期，以及 Codex 五小时**剩余额度**进度条/百分比。左侧是专辑封面、橙色播放进度、已播放/总时长、上一首/播放暂停/下一首和 ChatGPT 任务状态；右侧是歌名、歌手和歌词。右下“应用”返回菜单。

播放时中央按钮显示方形（点击暂停）；暂停时显示三角形（点击播放）。任务状态以圆形标记运行中、方形标记空闲中，断联显示未连接。额度过期时显示 `--`，不会把未知额度当成 0%。状态及额度复用时钟页的真实后台数据。

## 平滑歌词

S3 解析原始 LRC，在板上绘制歌词位图缓存，再以 480ms 缓入缓出的位移过渡切换。相同时间戳的原文与译文合并成同一个显示组，不再只选择最后一行。长句会换行，必要时在当前组横向滚动。暂停时播放时间和歌词位置保持；主动跳转到另一播放位置时直接定位，避免堆积过期歌词。

Windows 上报的 Position 是 LastUpdatedTime 时刻的位置；采集器按这个时间戳推进，USB 发送时再补偿传输等待，避免反复把 S3 的歌词时钟拉回旧位置。上游歌词时间戳本身不准确或歌词缺失时，缓存和动画不能修复源数据。

## 播放控制

S3 将触摸转换成 USB 控制事件，后台通过当前 Windows 音乐会话发送上一首、下一首、播放或暂停，并回传执行结果。图标以播放器实际状态更新，不以按钮点击猜测播放状态。不支持控制或没有播放器会话时显示未响应。命令按事件 ID 去重，USB 重连不会重放同一次切歌。

当前主要验收播放器为 QQ 音乐；播放器需要向 Windows 提供媒体会话与控制能力。

## 本地持久缓存

安装器自动创建 `%LOCALAPPDATA%\DeskHub\cache\music\v1`，按播放器来源与歌曲 ID 的 SHA256 建立子目录：

- `metadata.json`：歌名、歌手、专辑、时长、LRC/纯文本歌词、缓存版本及封面校验值。
- `cover.bin`：原始 PNG/JPEG 封面，不在电脑上缩放或渲染。

命中缓存时立即提供封面与歌词，缺少的资产才重新获取。首次遇到歌曲仍需要获取数据；没有歌词、未完成获取和网络失败不会伪装成有效歌词缓存。封面 SHA256 不符或 JSON 损坏时忽略并重新获取。重新启动后台及升级安装会保留缓存。

缓存定期按最久未使用清理，目标上限 512MiB / 1000 首。卸载后台会一并删除它。缓存和账号凭据不打包到项目源码或安装器中。清空缓存需先关闭 DeskHub 后台，再删除上述缓存目录，重新启动后自动建立。

## 升级

本版需要新版固件和 Windows 1.4.7 后台配套使用。完整解压 Windows 1.4.7 使用包后安装后台，再按刷机说明更新固件。安装不擦除原有缓存；USB 刷机不整片擦除，保留触摸校准、Wi-Fi 配置。原 110 秒视频彩蛋及其专用分区保持兼容。

开发验证：`python -m unittest discover -s desktop-usb/worker -p 'test_*.py'`；音乐采集器支持 `--self-test-cache <独立测试目录>` 验证缓存读写、路径和损坏数据处理。

接口参考：[Windows 媒体会话](https://learn.microsoft.com/en-us/uwp/api/windows.media.control.globalsystemmediatransportcontrolssession)、[时间戳与播放位置](https://learn.microsoft.com/en-us/uwp/api/windows.media.control.globalsystemmediatransportcontrolssessiontimelineproperties)。
