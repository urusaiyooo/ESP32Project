# Wi-Fi 配网与排查

ESP32-S3 使用 2.4GHz Wi-Fi。进入屏幕 Wi-Fi 设置，选择网络并输入密码；可以点击“显示”核对，输入栏同时显示长度。密码键盘的按键间隙不再计入按键命中。

连接前停止扫描和配网热点，重置无线接口，再开始新连接。界面区分连接热点和获取 IP 两个阶段。瞬时断开后最多重试 3 次；已关联但等待 IP 超过 10 秒时重新发起一次 DHCP 请求，总连接超时为 45 秒。只有成功取得 IP 后，才将新网络保存到项目配置。

## 根据阶段排查

- 未找到热点：确认热点提供 2.4GHz，检查距离与信号。
- 认证或握手超时：核对大小写、符号及加密设置，靠近热点重试。一次超时不足以判断密码错误。
- 已关联但未取得 IP：检查热点的 DHCP 服务、地址池与共享网段。固件重新启动 DHCP 成功，只能说明客户端调用成功，不能证明热点已响应。
- 企业网络：屏幕配网暂不支持需要用户名的 WPA2 Enterprise。

两台 Windows 电脑串联开启移动热点时，要检查上游 WLAN 与本机热点是否使用相同 IPv4 子网。例如上游地址为 `192.168.137.x/24`，本机热点也使用 `192.168.137.1/24`，就存在重叠网段。优先让 ESP32 直接连接第一台电脑提供的 2.4GHz 热点，或在可管理的上游设备处规划不同网段。

本次单设备排查观察到认证超时，以及完成关联但未取得 IP；同时确认两层 Windows 热点存在重叠网段，尚未完成消除冲突后的连接成功验收。试改 Windows ICS 注册表网段未被移动热点采用，已恢复电脑原设置。该电脑端试验脚本不属于固件功能，也不随项目发布。

## 串口诊断

通过项目 USB 控制通道发送 `HUB_WIFI_STATUS`，返回 `WIFI_UI` JSON：

- `attempt`：0 空闲、1 连接中、2 成功并保存、3 失败、4 已连接但保存失败。
- `phase`：准备无线接口、连接热点、DHCP、在线或失败。
- `reason`、`disconnects`：驱动断开原因和次数。
- `associated`、`channel`、`auth`：当前关联状态、信道及认证方式。
- `dhcp_state`：0 初始、1 已启动、2 已停止；-1 表示无法查询。
- `has_ip`：是否拥有非零 IPv4 地址。

状态接口包含选中网络和扫描到的网络名称，不包含密码。公开日志前仍需移除个人网络名称。

`HUB_WIFI_RETRY` 使用设备内部上次站点配置重新尝试连接，不导出密码，也不代替输入新网络的凭据。失败后固件可能恢复旧网络或启动配网热点，此时部分实时无线字段描述的是恢复后的接口，应结合本次失败提示判断。

`WIFI_DIAG`、`WIFI_RECONNECT`、`WIFI_DHCP` 串口行记录恢复调用结果；不要把调用返回成功等同于最终联网成功。
